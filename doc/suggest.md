# 面试题学习建议

## 核心原则：先"说清楚"，再"写出来"

这些题考的不是背答案，而是**能否用自己的话讲明白**。建议每个知识点学完后，对着镜子或录音，不看稿说一遍。

---

## 按优先级分三层

### 第一层：必须滚瓜烂熟（项目直接相关）

这些是面试官必问的，答不好直接掉分。

**1. Git reset 三种模式**
- 核心：`--soft` / `--mixed` / `--hard` 对 HEAD、Index（暂存区）、Working Tree 三者的影响
- 学法：画一张三列对比表，动手在本地 `git init` 一个测试仓库，亲手执行三种 reset 看效果
- 关键输出：能解释 squash 为什么必须用 `--soft`

**2. Shell 注入 & execFileSync vs exec**
- 核心：shell 解析字符串 vs 直接传 argv 数组
- 学法：写一个 Node.js demo，分别用 `exec` 和 `execFileSync` 执行同一个带特殊字符的参数，观察差异
- 关键输出：能解释"参数数组为什么不会被 shell 解析"

**3. MCP 协议基本概念**
- 核心：Client / Server / Tool 三者关系，stdio 传输的工作方式
- 学法：看 [MCP 官方文档](https://modelcontextprotocol.io/docs) 的 Core Architecture 部分，20 分钟够了
- 关键输出：能回答"为什么选 MCP 而不是写个脚本"

---

### 第二层：能答出来加分（展示深度）

**4. 局限性那道题**

这道题是送分题，但很多人答不好，因为没有真正思考过。

- **分支感知**：理解 detached HEAD 是什么状态（`git checkout <commit-hash>` 后会进入）
- **并发安全**：了解文件锁（lockfile）的基本概念，Git 自己的 `.git/index.lock` 就是例子
- **aig_undo 丢失 stash**：理解 `git stash` 的作用和时机

学法：把这四个局限性每个都想一个具体的"复现场景"，面试时说"比如在 X 情况下会出现 Y 问题"，比干讲概念有说服力得多。

**5. 连续 Checkpoint 识别算法**

- 学法：自己重新实现一遍这段逻辑，不看代码，只看注释描述。能写出来说明真的理解了
- 延伸：思考如果不加 `break` 会出现什么 Bug，准备好具体例子

---

### 第三层：有余力再看（拓展加分）

**6. 为什么用 stdio 而不是 HTTP**
- 了解进程间通信（IPC）的几种方式：stdio、Unix socket、HTTP，各自的适用场景
- 理解"本地工具"和"网络服务"的安全边界差异

**7. TypeScript ESM 模块**
- 理解为什么 `import` 路径要写 `.js` 后缀（TS 编译到 ESM 的规则）
- 了解 `tsup` 是干什么的，和 `tsc` 的区别

---

## 实操建议（最重要的一条）

**把整个项目重新讲一遍给别人听**，或者写一篇"我是如何设计这个项目的"博客草稿。

能讲清楚 = 真的懂了。讲不清楚的地方 = 还需要补的地方。

这比刷题有效得多，因为面试官问的任何问题，本质上都是在问"你真的做过这个吗"。
